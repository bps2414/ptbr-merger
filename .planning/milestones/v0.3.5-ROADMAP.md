# Milestone v0.3.5: Hygiene Baseline

**Status:** SHIPPED 2026-03-25
**Phases:** 1-1
**Total Plans:** 3

## Overview

This milestone closed the brownfield planning reset by restoring repository hygiene around PTBRMerger's existing codebase. The shipped scope was intentionally narrowed to Phase 1 only: re-establish a sane tracked-versus-local boundary, document it, and stop runtime/tooling noise from polluting source control.

Phases 2-4 were defined during planning but explicitly deferred before execution by product decision, so they are not part of this shipped milestone.

## Phases

### Phase 1: Repo Hygiene Baseline

**Goal**: Re-establish a sane repository boundary between source code, planning artifacts and local runtime outputs.
**Depends on**: Nothing (first phase)
**Plans**: 3 plans

Plans:

- [x] 01-01: Audit current tracked vs untracked runtime artifacts and define the intended repository boundary
- [x] 01-02: Restore or correct ignore rules for caches, logs, runtime ledgers and local config handling
- [x] 01-03: Update documentation so contributors know the clean workflow

**Details:**

- The milestone created a repository boundary audit documenting tracked artifacts, local-only runtime files, generated noise classes, and safe cleanup rules.
- `.gitignore` was restored with explicit exclusions for Python caches, local config, runtime ledgers/logs, and local tooling workspace artifacts.
- Previously tracked `.pyc` files were removed from the git index and cache directories were deleted from the workspace.
- `README.md` gained a concise `Repository Hygiene` section so contributors can understand the tracked/local split without reading planning docs.
- UAT passed with 3/3 checks, confirming quieter `git status`, tracked `.planning/` files, and correct README guidance.

---

## Milestone Summary

**Key Decisions:**

- Use `.gitignore` plus concise README guidance as the durable repository boundary contract.
- Treat `.planning/` as intentional tracked project state, not disposable local tooling output.
- Preserve `config.yml` and runtime ledger files locally while removing their source-control noise.

**Issues Resolved:**

- Missing `.gitignore` causing runtime state and tooling artifacts to flood `git status`
- Tracked Python bytecode files lingering in the repository index
- No concise contributor-facing explanation of what should stay tracked versus local-only

**Issues Deferred:**

- Phase 2: Trigger decomposition
- Phase 3: Ranking domain extraction
- Phase 4: Validation workflow

**Technical Debt Incurred:**

- None in shipped scope beyond the already-known product/code maintainability work deferred to a future milestone
